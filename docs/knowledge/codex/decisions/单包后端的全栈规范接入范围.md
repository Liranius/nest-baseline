# 单包后端的全栈规范接入范围

本项目采用 `ai-workflow-research` 全栈工程规范 v1.14 中适用于单包 NestJS 服务的仓库治理要求。对应规范位于研究仓库的 `docs/全栈工程/README.md` 和 `docs/全栈工程/monorepo/工程规范.md`，本次核对版本为 `e6b3e0a`。

- [decision] 当前基线覆盖可复现安装、只读质量检查、服务启动与生产冒烟、项目维护、提交前检查和 GitHub 合并保护。运行步骤和维护职责见[项目 README](../../../../README.md)。
- [scope] 基线最初约定在 API 提供方、消费方和业务失败场景明确后确定契约与验收用例。整合设备预约参考实现后，员工端和管理端通过 HTTP 使用预约服务，双实例验收覆盖时段冲突、权限拒绝和幂等重试，并按 [OpenAPI 契约](../../../openapi.json)核对响应。项目仍使用单包结构，前端和多包条款随项目结构变化重新评估。
- [decision] TypeScript 检查项目加载的声明文件。2026-11-17 核对锁定依赖后移除了 `skipLibCheck`。完整类型检查通过，临时声明文件引用未知类型时，项目的 `typecheck` 按预期报告 `TS2304`。
- [decision] 采用本地 Basic Memory，让后续会话能查到采用规范的依据。笔记随 Git 审查，索引按 worktree 隔离，以便不同分支可以各自修订决定。[项目知识指南](../../../project-knowledge.md)

2026-11-17 核查 `main` 的 `31f5f63` 时，GitHub 要求 PR 与目标分支同步、`Quality` 通过，并对管理员执行保护。仓库仅允许 rebase merge，当时所需的人工批准数为 0。复查时以 GitHub 分支保护设置为准。

[PR #1](https://github.com/Liranius/nest-baseline/pull/1) 记录了测试失败、运行取消、跳过步骤和跳过整个检查任务时的合并拦截，以及修复后恢复可合并的结果。[PR #3](https://github.com/Liranius/nest-baseline/pull/3) 记录了提交前修复、部分暂存、重命名、删除和无匹配文件的验收。[主分支 CI](https://github.com/Liranius/nest-baseline/actions/runs/44063054147) 可核对该提交的冻结安装与完整质量检查。
